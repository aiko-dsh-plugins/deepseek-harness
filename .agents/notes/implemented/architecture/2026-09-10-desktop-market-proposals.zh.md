# Agent Note: 桌面市场包变更请求

Status: implemented

[English](2026-09-10-desktop-market-proposals.md) | 中文

## Problem

独立插件目录分发依赖及 GitHub 发布归档，而 Desktop 拥有隔离的包项目，仅向受信任的管理窗口开放安装操作。市场插件不能使用 Web 路由或通过 CLI 修改保留 profile。

## Decision

应用渲染进程可以提交结构化安装与卸载请求。Electron 验证发送方和数据，在原生确认窗口展示每个包的来源，再通过现有事务项目管理器执行获准请求。批次保留依赖顺序，共享一次健康检查与激活。包元数据记录远程来源，以便发布校准时离线恢复；发布拥有的包不能被替换，其他插件需要的依赖不能被卸载。

目录加载、依赖规划和业务界面仍由独立分发的插件提供。桌面壳不包含组织目录或业务包名。沙盒预加载程序分别构建，避免共享 IPC 常量被生成为本地 CommonJS 分块。

发行配置的预装插件表将已发布的可选 bundle 加入离线 seed。首次安装激活它们；发布校准恢复活跃插件清单，包括卸载结果和独立更新后的来源。预装不授予发布拥有的保护：原生管理器可以卸载默认插件，后续应用发布不能静默恢复它。这使市场在首次使用时即可用，同时不成为永久核心依赖。市场从目录卡片中排除其自身发行记录，在页头保留已安装版本。

## Alternatives considered

直接给市场文件系统或 pnpm 权限会绕过 staging 和恢复。加载工作区插件无法验证发布目录来源。仅允许 npm 会排除组织现有的发布制品。原生确认使安装权限仍归 Electron，同时允许目录提出下载来源。

## Consequences

Desktop 包含一项需要与兼容市场版本配套的集成修改。市场安装请求仅在确认后才能重启后端并刷新应用。源码开发 profile 仍不可修改。定向测试覆盖请求拒绝、依赖顺序、来源保留、依赖保护、首次预装、卸载保留和回滚；安装制品检查验证私有 Host 与实际内置包管理器。
